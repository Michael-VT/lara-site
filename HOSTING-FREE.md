# Бесплатный хостинг для IX Lara Handmade

Этот сайт — **полностью статический** (SvelteKit + `@sveltejs/adapter-static`). Команда `bun run build` собирает готовый набор HTML/CSS/JS/изображений в папку `build/`, после чего для работы сайта **не нужен ни Node.js, ни какой-либо сервер с бэкендом** — только раздача статических файлов. Это открывает доступ ко всем бесплатным статическим хостингам без исключений и ограничений по типу проекта.

Особенности, которые учитывались при выборе вариантов:

- 4 языка с префиксами в пути: `/en/…`, `/pt/…`, `/uk/…`, `/ru/…`.
- Кастомная страница 404 (`404.html`) — хостинг должен уметь отдавать её на несуществующие пути.
- Генерируется `sitemap.xml` (скрипт `generate:sitemap`), зависящий от `siteUrl` из `src/lib/config/site.js`.
- Сборка запускается командой `bun run build` (использует Bun, но большинство хостингов также нормально собирают проект через `npm`/обычный Node, если Bun недоступен — см. примечания по каждому варианту).

## Обязательно перед первым деплоем

1. **Указать реальный домен.** В `src/lib/config/site.js` сейчас стоит заглушка:
   ```js
   export const siteUrl = 'https://ixlara.example';
   ```
   Замените на настоящий адрес сайта (даже если это бесплатный поддомен вида `ix-lara.pages.dev`) — иначе `sitemap.xml` и SEO-теги (canonical, hreflang, Open Graph) будут указывать на несуществующий домен.
2. Там же `isDemoContent = true` — при желании отключить как индикатор "демо" (используется скриптом валидации контента, не влияет на публикацию).

## Сравнение бесплатных вариантов

| Хостинг | Лимиты бесплатного тарифа | Свой домен бесплатно | HTTPS | Деплой из Git | Особенности для этого проекта |
|---|---|---|---|---|---|
| **Cloudflare Pages** | Безлимитный трафик, 500 сборок/мес | Да | Авто | Да (авто-деплой при пуше) | Лучший вариант: нет лимита по трафику, глобальный CDN, поддерживает Bun из коробки |
| **Netlify** | 100 ГБ трафика/мес, 300 мин сборки/мес | Да | Авто | Да | Простая настройка `_redirects`/заголовков кэша, если понадобится |
| **Vercel** | 100 ГБ трафика/мес (Hobby) | Да | Авто | Да | Отличная интеграция с SvelteKit, но некоммерческое использование по условиям Hobby-тарифа |
| **GitHub Pages** | 100 ГБ трафика/мес, 1 ГБ на сайт | Да | Авто | Да (через GitHub Actions) | Нужен `paths.base` в конфиге `sveltekit()` (`vite.config.js`), если сайт не на корневом домене/user-странице |
| **GitLab Pages** | ~Без строгого лимита трафика (fair use) | Да | Авто | Да (через `.gitlab-ci.yml`) | Похоже на GitHub Pages, тоже может требовать `base` для под-пути |
| **Firebase Hosting** | 10 ГБ трафика/мес, 360 МБ/день | Да | Авто | Через CLI (`firebase deploy`) | Хорошо, если уже используете другие сервисы Google |
| **Surge.sh** | Без строгих лимитов (для личных проектов) | Да (платно за некоторые фичи, базовое — бесплатно) | Через Cloudflare/сторонний прокси | Только CLI, без авто-деплоя из Git | Проще всего для разового ручного деплоя одной командой |
| **Render (Static Site)** | 100 ГБ трафика/мес | Да | Авто | Да | Простая настройка, но чуть медленнее холодного старта на бесплатном плане |

## Рекомендация

**№1 — Cloudflare Pages.** Безлимитный трафик — важно для карточек товаров с фотографиями, глобальный CDN (быстро грузится и в Португалии, и в Украине), поддержка сборки на Bun «из коробки», бесплатный SSL и лёгкое подключение своего домена.

**№2 — Netlify.** Чуть более гибкая настройка (заголовки кэша, редиректы), тоже отличный вариант, если Cloudflare по какой-то причине не подойдёт.

### Пошагово: деплой на Cloudflare Pages

1. Зарегистрируйтесь на [pages.cloudflare.com](https://pages.cloudflare.com) (бесплатно).
2. Загрузите код в GitHub/GitLab (если ещё не сделано) и подключите репозиторий к Cloudflare Pages.
3. Настройки сборки:
   - **Framework preset:** SvelteKit
   - **Build command:** `bun run build`
   - **Build output directory:** `build`
   - **Environment variable:** добавить `PUBLIC_PRODUCTION=true` (используется скриптом проверки контента) — не обязательно, но полезно.
4. Cloudflare соберёт и опубликует сайт на бесплатном поддомене `*.pages.dev`, HTTPS включится автоматически.
5. Чтобы подключить свой домен: **Custom domains → Add a domain** и следуйте инструкции (просто добавить CNAME/NS-запись). Домен нужно будет купить отдельно (домен и хостинг — это разные вещи), например у Cloudflare Registrar, Namecheap или Reg.ru — от ~10€/год за `.com` или похожий.
6. Каждый `git push` в основную ветку будет автоматически пересобирать и обновлять сайт.

### Альтернативы — кратко

- **Netlify:** New site from Git → Build command `bun run build` → Publish directory `build` → Deploy.
- **Vercel:** Import Git Repository → framework определится как SvelteKit автоматически → Deploy.
- **GitHub Pages:** нужен workflow в `.github/workflows/deploy.yml`, который выполняет `bun run build` и публикует папку `build` через `actions/deploy-pages`. Если сайт будет по адресу `username.github.io/repo-name` (а не на своём домене), добавьте в `vite.config.js` в `sveltekit({...})` опцию `paths: { base: '/repo-name' }`.
- **Surge.sh:** локально выполнить `bun run build`, затем `npx surge build/ your-site-name.surge.sh` — деплой за 30 секунд, без Git.

## О доменах

Все перечисленные хостинги **бесплатно дают поддомен** (`*.pages.dev`, `*.netlify.app`, `*.vercel.app`, `username.github.io` и т.д.) и **бесплатно позволяют подключить свой домен** — платным будет только сам домен (регистрация и продление, обычно 8–15€/год), а не его подключение к хостингу.

## После деплоя — проверить

- Открыть `/sitemap.xml` и убедиться, что ссылки указывают на правильный домен.
- Проверить, что несуществующий адрес отдаёт кастомную страницу 404, а не стандартную страницу хостинга.
- Проверить переключение языков (`/en/`, `/pt/`, `/uk/`, `/ru/`) и работу мобильного меню.
- Проверить, что HTTPS включён (обычно автоматически на всех перечисленных хостингах).
